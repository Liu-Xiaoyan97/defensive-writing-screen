# Defensive Writing Screen

Four phases, in this order: **the questions pass a control battery → Jev triages every prose unit → the agent verifies the highest-probability candidates → the agent rewrites only what it has confirmed.** Skipping verification turns a screening signal into an automated deletion policy, which this skill never authorizes. Skipping the battery turns a compressed probability scale into a false clean bill of health.

This skill is self-contained. It requires no other skill, and no other skill overrides its rulebook. `references/rewrite-guide.md` is the complete, operative rewriting authority here: read it in step 6 and follow it directly. Do not delegate rewriting to, wait for, or require `anti-defensive-writing` or any other installed skill, even when one is present; treat its absence as irrelevant to whether this skill can run.

Cost model: triage is cheap and parallel, so screen broadly; reading and rewriting are expensive, so spend them only on candidates plus a small sample of rejects.

## SOP

1. **Scope and authority.** Read the requested draft and only the context needed to interpret it. Follow the user's instructions and the applicable project rules. A skill, a threshold, or a Jev probability never authorizes an edit. If no draft or target is identifiable, ask for one. Keep project-specific rules out of this skill's files; supply them as state when relevant.
2. **Prepare units and candidate spans.** Use `scripts/prepare_units.py --candidates` or an equivalent split. One unit is one prose paragraph, with a stable location (file, section, line, paragraph number) and verbatim source text. Skip code fences, display math, tables, bibliographies, and quoted third-party passages unless the user asks; keep table and figure captions, which are authorial prose. Attach nearby context and only evidence you actually have. Never invent experimental facts, sample sizes, or causal claims.
3. **Run the control battery before screening.** Screen the four positive and two negative controls in `references/cases.md` with the exact questions and state shape you intend to use, in the language of the document being screened. The battery passes only when every positive control reaches its designated dimension at or above the routing threshold, and no negative control exceeds 0.20 on any dimension. Marker lists are language-specific: a batch of English anchors left a mild Chinese modesty sentence at 0.375, and the same sentence reached 0.991 after Chinese markers were added. If the battery fails, the questions do not separate defensive from neutral prose for this language, genre, and model version: rewrite the `instructions` before screening the document. A document screened under a failing battery yields no usable result, and its low scores are not evidence that the document is clean. Report the six measured values with the result. Calibration records in this skill stay generic: control sentences, question-level values, and aggregate screening statistics, with no project content, document identity, field-specific nouns, or draft excerpts. Project material stays in the project and enters only as run-time state.
4. **Jev triage with the observable question set.** One paragraph per request; ask `claim_negation`, `negative_contrast`, `vague_hedge`, and `concessive_hedge` in one call. Do not route on `repeated_scope` or `repeated_fact`: measured on a genuine restatement they return 0.29 and 0.36, and a constructed redundant control scores 0.38 against 0.34 for neutral prose, so they cannot separate the class. Repetition is an agent-side check, described in step 6. The request shapes are in `references/questions.md`. The instructions must carry markers from the document's language: English anchors alone scored a mild Chinese modesty sentence at 0.375, while the same sentence reached 0.991 once Chinese markers were named, so translate the marker list before screening. These questions ask what the text contains, not whether the text is justified: sufficiency questions ("does this add anything?") score the canonical defensive sentences at 0.23-0.45, below this skill's own gate, and compress a whole document toward zero. Every `instructions` field names its target by state path; IDs stay invisible to Jev. Define `criteria.true` and `criteria.false` so the yes-probability has one meaning. For each deterministic candidate span, send the focused `removal_preserves` request in a separate, flat call. Do not ask Jev for rewrites, verbatim quotes, permissions, or a holistic writing score.
5. **Route candidates.** Per unit, `triage_probability = max(claim_negation, negative_contrast, vague_hedge, concessive_hedge)`, with `repeated_scope` and `removal_preserves` kept as separate columns. Review every unit at or above 0.65, highest first, and record the others as `not_selected`. The threshold decides what enters review first; it never decides a verdict. On large drafts, batch the review in document order and keep the per-unit record. Expect low candidate precision: in calibration screening about a third of candidates survived verification, and conditional-baseline framing (`if only X were used`, 若仅采用) accounted for most of the rejects in a method-heavy draft. Report the candidate count and the confirmed count instead of presenting candidates as defects. Below threshold means "not selected", never "clean"; resample below-threshold units during adoption to estimate misses. A failed call means triage is incomplete; say so and do not present a substitute as a Jev result.
6. **Agent verification.** Read every unit, not only the routed ones. For a routed unit, start from its score; for a unit marked `not_selected`, apply the checklist directly, because the screen is silent there and silence is not a verdict. Record one verdict per unit: rewrite, or keep with a category (definitional, reported result, necessary scope, conditional baseline, conceptual contrast, constraint, reference). Run the repetition check by hand: in a method or results paragraph, look for a second sentence that restates a fact, restriction, or scope condition already stated in the same paragraph. The screen cannot see this class, so the agent owns it. Classify each flagged item as unnecessary defense; necessary scope or uncertainty; meaningful conceptual contrast; conditional baseline; technical prohibition; safety, legal, or ethical condition; unfavorable result; or unresolved. The commonest false positives are conceptual contrast and conditional baseline. Keep a contrast when it carries the argument itself, such as a notation distinction, a mechanism difference, an operating condition, or an intervention setup fact. Keep a conditional when it defines the baseline the design is measured against ("if only a single value were used", 若仅采用单一取值), because the limitation belongs to the method class being described, not to the proposed design. Inside such a conditional, distinguish a constraint that names its object from a difficulty that names nothing: 只能… and 无法… with a stated object stay, while 难以… without a bound is a vague weakening and may be rewritten while the conditional clause itself stays. The screen surfaces this only when the rest of the unit carries enough signal: constructed instances scored 0.030, 0.437, and 0.706, and the stronger wording scored lower than the milder one, so treat the distinction as an agent judgment and reach such units through the candidate search. Keep any qualification that affects the validity of the claim, the interpretation of the evidence, the scope of application, the research design, or the reader's ability to use the result. Keep mathematical conditions, experimental intervention scope, metric direction, and unfavorable results even when they read as negative framing. A change requires a high dimension score plus an agent finding that no necessary meaning is lost. For a deletion, also require a high `removal_preserves`. For a rewrite, a low `removal_preserves` is expected when the span carries a fact: the question then vetoes deletion, not restructuring, and the rewrite must carry every fact the span carried. A high probability alone is never a finding. Load `references/rewrite-guide.md` before writing any replacement. If the evidence needed to judge a claim is missing, name what is missing instead of guessing.
7. **Confirm, rewrite, and post-edit check.** Present, per unit with a verdict: for rewrites, the exact source span and one local revision that preserves every fact, number, condition, and unfavorable result; for keeps, the category. For a routed unit, also give the dimension and probability that routed it. Build the per-unit record with `scripts/merge_verdicts.py`, which joins the screen file, the verdict file, and an optional independent label file and prints agreement, recall on labelled rewrites, and routing precision. When the result is cross-checked against another pass, that pass must be produced without examples or ids from the document, and every disagreement is adjudicated in writing. Say briefly why rejected items stay. Never strengthen a claim beyond its evidence to make prose sound more confident, and never weaken one to avoid a hypothetical objection. Rewrite files only with explicit authorization. Then compare the revised text against the original facts, numbers, units, metric direction, and required conditions, and re-run the same battery and the same questions on the revised prose. State plainly which checks ran and which did not.

## Working without Jev

If no System One caller is available, run steps 1-2, skip steps 3-5, and perform steps 6-7 on the agent's own reading of every unit, with the detection checklist in `references/rewrite-guide.md`. Report the mode as `agent-only, Jev triage skipped`. Do not describe the result as Jev-verified, and do not lower the review standard to compensate.

## Reporting

- Scope: document, sections or line ranges, unit count, exclusions.
- Calibration: model and version, the six battery values, pass or fail, and the threshold in use.
- Triage: per-unit dimension probabilities, routing threshold, candidate count, confirmed count.
- Verification: exact excerpts, keep or change decision, classification, reason, and one proposed revision each.
- Coverage and limits: below-threshold sampling, untriaged units, Jev or validation failures, and checks not run.

Files: `scripts/merge_verdicts.py` (per-unit record and agreement counts), `references/questions.md` (calibrated request shapes, thresholds, failure handling), `references/rewrite-guide.md` (complete bundled rewrite rulebook, the only rewriting authority), `references/cases.md` (control battery, labeled smoke tests, measured runs), `scripts/prepare_units.py` (offline paragraph and candidate-span extraction). Every capability this skill needs is inside this directory; installing another skill adds nothing and removing another skill takes nothing away.
