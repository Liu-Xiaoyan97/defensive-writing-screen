# Defensive Writing Screen

This skill requires no other skill. Read its bundled `references/rewrite-guide.md` directly; do not load or defer to another writing skill. Upstream names record provenance, not a runtime dependency. User instructions and applicable project rules retain priority.

Default sequence: **control gate → Jev triage → agent verification → suggestions**. File edits need explicit authorization. A probability is a routing signal, never an editing permission or a confirmed defect.

## SOP

1. **Scope and authority.** Identify the draft, genre, language, authorized sections and output. Record its version or hash. Read only relevant context and available evidence. Do not invent results, causal links or restrictions. Calibration records in this skill stay generic: no project content, document identity, or draft excerpts. Runtime state and reports may contain the user's draft; keep them outside the skill package.
2. **Prepare units.** Use `scripts/prepare_units.py --candidates` or equivalent extraction retaining line ranges and original text. `.tex` selects the conservative LaTeX mode; use `--format latex` for stdin. Keep abstract, authorial captions, lists and prose around equations; omit mathematical displays, table cells, bibliography and layout commands. Inspect extraction coverage against the source. The script does not expand macros, includes or arbitrary TeX; report unsupported constructs and read them directly. Candidate spans are retrieval hints, not grammatical analyses.
3. **Structure check.** Use `scripts/check_structure.py`, then read section transitions. Report S1 missing conclusion, S2 ending on limitations, S3 missing necessary scope statement, S4 absent/folded related work, S5 evidence distant from its claim, S6 redundant implementation detail inside a review. These are document-level observations, not automatic defects. Genre and venue determine required roles. Research positioning at the end of related work is legitimate. Give a concrete reason and destination for any proposed move.
4. **Control gate.** Load the exact four active questions and all six controls from `references/controls.json`; `references/questions.md` explains the contract. Run one control per request using the same state shape as the draft. Each of four positive controls must reach its designated dimension at 0.65 or above; both neutral controls must be at or below 0.20 on every active dimension. Record all values and requested/resolved model identifiers separately. Also review the semantic challenge cases in that file; they test agent decisions, not classifier separation. Do not silently change questions, labels, controls or thresholds to pass. A control call may be retried once for a transport error, not for an undesirable score. A completed failing gate blocks draft Jev calls for this run and switches to the explicitly reported agent-only diagnostic mode below. Any question development belongs to a separate calibration run, not this document audit.
5. **Jev triage.** After a passing gate, ask `claim_negation`, `negative_contrast`, `vague_hedge`, `concessive_hedge` together, one paragraph per request. Use exact questions from controls.json. Record raw responses and per-unit values. Translate markers and create a matching control set before auditing a different language; report it as a separate question variant, never inherit English gate validity. `scope_tail` is retired from default routing in 0.11.0 after failing controls; repetition is also agent-side only. Neither is a zero-valued probability. For deterministic candidate spans and any proposed deletion, obtain the focused `removal_preserves` judgment with whole-paragraph context and known evidence; retain exact spans and raw values. It tests deletion, not whether equivalent restructuring is permitted. Retry a failed call once; record persistent failures as `untriaged_error` with null values.
6. **Choose the review scope, then verify.** `triage_probability` is the maximum of the four active values. Select one scope before reading and report it. `screened` reads every routed unit (>=0.65), every focused candidate, the 0.45-0.65 band when it is small, and a stratified sample of the remaining units: all of them when there are 20 or fewer, otherwise at least 20 spread across the document, labeled in the record. `full` reads every unit and is required when the user asks for exhaustive review, when the draft is being accepted for publication, or when Jev was not used. In `screened` mode, count the misses found in sampled non-routed units and report that observed rate with the sample size instead of claiming recall. Low scores mean `not_selected`, not clean, and an unsampled unit stays unread in the report. Keep null for unrun/failed judgments. Read the bundled guide before proposing a revision. Protect P1 results/directions, P2 proof conditions, P3 measurement/reproduction conditions, P4 intervention scope, P5 design premises, P6 comparison semantics. These protect meaning, not exact wording: retain facts while independently judging framing. A clear ranked comparison is not defensive just because its numbers appear elsewhere. Read the whole paragraph and neighboring context before judging a backward reference; do not demand repeated conditions in every sentence. With insufficient context, keep the qualifier or request clarification rather than delete it.
7. **Record independent findings, including dispositions.** Each read unit has a summary verdict plus a `findings` array with separate exact spans, rule/action IDs, protection classes, reasons and proposals. Multiple R rules may apply to different spans in one unit, and every sentence of a read unit is inspected even after the first finding. Each routed unit also needs one line naming the dimension, the score and why it ended as a finding or a keep. R1 vague weakening, R2 concessive/self-undermining framing, R3 empty disclaimer, R4 empty contrast, R5 redundancy without a navigation/inference role, R6 genuinely empty retreating qualifier. R6 requires evidence that no restriction, uncertainty or useful contextual reference is lost; deictic wording alone is not enough. Narrative actions: N1 restate emphasis without changing rank, N2 narrow unsupported claims (not all interpretations of numbers), N3 relocate with a named receiving location. Keep categories K1 definitions, K2 results, K3 conditional baselines, K4 constraints, K5 scope, K6 meaningful contrasts, K7 captions/roadmaps. A finding is `confirmed` when the bundled guide lists the construction as a rewrite rule, the revision preserves every fact, and the current wording weakens a supported claim or a supported unfavorable result through framing rather than content; a concession whose facts all survive is therefore confirmed, not optional. A finding is `optional` when the text is not defensive and the change is presentation: restating an already clear condition, importing numbers from a table, merging sentences, or reordering material. Structural observations are not span rewrites.
8. **Report only what carries risk.** The response records findings, one line per routed unit, one aggregate line per sampling group, structure observations and cost facts. Units below the threshold that were read and produced no finding get no individual record; they appear only in the aggregate count. A finding below the threshold is recorded whenever it exists, because a low score never suppresses an observed problem. Write the full per-unit table to a file artifact such as `screen.jsonl` or `per-unit-table.md` and reference its path; never inline 100+ rows, since record size, not reading, drives agent cost. Keep the response near 60 lines unless the user asks for the complete ledger. Give exact source/line, finding type, disposition, evidence, smallest revision and facts preserved, along with the keep record for every routed unit. In Jev mode, disclose all probabilities and how each item was reached (routed, focused, sampled, direct agent review); a low score does not veto a separately justified agent finding. For deletion in Jev mode require a high focused value plus agent verification; missing/low focused values mean keep or restructure without deletion. In agent-only mode, deletion suggestions must explicitly lack Jev validation. Use `scripts/merge_verdicts.py` for the per-unit record; null remains untriaged, and span findings survive the merge. Compute precision only for genuinely routed units, and agreement only against independent labels. Report cost as measured facts and keep them separate from quality: review scope, units read and unread, Jev requests including retries and failures, and agent turns or tokens when the caller exposes them. Do not describe a Jev-first run as cheaper than an agent-only run unless a measured comparison on the same draft supports it; a Jev-first run that also reads every unit cannot save agent work by construction. Suggestions alone do not authorize edits. After authorized edits verify numbers, units, direction, conditions and source integrity, then rerun applicable checks. Report what did not run.

## Working without Jev

No caller, a completed failing gate, or a persistent gate transport failure triggers **agent-only diagnostic review**. Do not tune during the audit. Continue steps 1–3 and 6–8, using all bundled rules and semantic challenge cases. Mark every draft probability null and use `untriaged_no_caller`, `untriaged_control_failed`, or `untriaged_error`. Report why Jev was skipped; never call this a successful Jev workflow. Partial draft failures may coexist with successful records but overall screening is incomplete. Infrastructure failures and classifier failures are different outcomes.

## Reporting

- Version/hash, scope, genre, unit/exclusion counts, extraction caveats.
- Control question revision, all six control rows, model alias and resolved version if returned, pass/fail and retry history.
- Review scope (screened or full), units read, units sampled, units unread, and the observed miss rate with its sample size when sampling was used. Do not enumerate silently read units.
- Triage and verification counts separately; agent-only or partial status prominently.
- Per-unit records, one line per routed unit, and independent span findings with disposition (confirmed or optional), protection classes and keep reasons.
- Structure separately, with proposed receiving locations and a note that a single model pass is weak evidence for a structural finding.
- Cost facts: Jev requests, retries, failures, agent turns or tokens when available.
- No claim of recall, accuracy or cost benefit without independent labels and measured comparison on the same draft. Jev prioritizes review and structures the record; it does not by itself reduce reading.

Files: `references/controls.json` (canonical active questions, six gate controls and semantic challenges), `references/questions.md` (protocol and categories), `references/rewrite-guide.md` (self-contained rewriting authority), `references/cases.md` (current and historical calibration boundaries), `scripts/prepare_units.py`, `scripts/check_structure.py`, `scripts/merge_verdicts.py`.
